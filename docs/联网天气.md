# 联网天气查询

语音识别仍在电视本地完成。JSON 命中 `check_weather` 后，后台线程发起 HTTPS 请求，主线程显示天气结果。音频和整句识别文本不会发给天气服务。

## 使用方式

- “北京天气”“查一下上海现在的天气”：当前天气、气温、体感温度、湿度。
- “北京今天天气”“明天上海天气”“后天天气预报”：指定日期的白天/夜间天气、最高和最低温度。
- “天气”“今天天气怎么样”：默认通过电视的公网 IP 定位。结果明确标注“IP 定位”；宽带出口、VPN 或代理可能导致城市偏差，直接说城市名称即可覆盖。
- “天气预报”未说日期时查询今天；普通“天气”未说日期时查询当前。
- 同名城市有多个精确结果时，弹出列表供遥控器选择，避免自动选择错误地区。

主界面右侧的“天气设置”可以填写 API Host、API KEY 和可选的固定城市。固定城市留空时使用 IP 定位。配置保存在应用私有的 `no_backup/weather.json`，不进入 Android 备份，也不放进指令 JSON。

本项目的 API Host 已预填为 `jw6939gar5.re.qweatherapi.com`。开发者 ID、项目 ID、凭据 ID 都不能代替 API KEY。当前接入使用请求头 API KEY；JWT 签名和令牌续期尚未实现。

## 本地开发配置

当前账号已创建项目 `LeVoice语音天气`，凭据仅启用 GeoAPI 和天气预报。真实密钥保存在项目根目录的 `weather.local.json`，文件权限为 0600，并已加入 Git 忽略规则；APK 不包含它。

安装 debug APK 后，可以在电视的“天气设置”中填写凭据，也可以用下面的脚本通过 ADB 写入应用私有目录（不经过共享存储，不在命令行参数中携带密钥）：

```bash
python3 scripts/configure_weather.py --serial 电视IP:5555
```

脚本写入后会回读校验，但不会输出密钥。重启应用后生效。脚本依赖已连接的 ADB 设备和可使用 `run-as` 的 debug 安装包。

## 分层

| 文件 | 职责 |
| --- | --- |
| `JsonHttpClient.kt` | 可复用 HTTPS GET、JSON 解码、Gzip、连接/读取超时、响应体大小限制、取消 |
| `LatestRequestRunner.kt` | 后台任务执行；丢弃旧查询结果，页面离开/销毁时取消 |
| `IpLocationClient.kt` | 未指定城市时，通过公网 IP 获得近似坐标，不发送天气密钥 |
| `QWeatherTls.kt` | 为旧 Android 补充官方 ISRG Root X1，仅作用于和风天气域名，保留完整证书及域名校验 |
| `QWeatherClient.kt` | 城市查找、当前天气、每日预报、错误翻译与缓存 |
| `WeatherSettings.kt` | 天气连接配置校验、应用私有文件保存 |
| `WeatherController.kt` | 查询进度、天气结果、同名城市选择、设置表单 |
| `CommandExecutor.kt` | 调用已注册的 builtin 处理器，并区分同步完成与异步等待 |

新联网业务可以复用 HTTP 层和任务执行器，注册新的 builtin 处理器。天气接口的响应解析属于天气模块；不会把不同业务的 HTTP 请求塞进 Intent 构造逻辑。

## JSON 配置

新增可选字段 `action.builtinParams`，其值是字符串映射，支持现有 `$param1` / `${param1}` 变量替换：

```json
{
  "id": "weather_example",
  "displayName": "查询城市天气",
  "regex": "^查询(.+?)天气$",
  "action": {
    "type": "builtin",
    "builtinAction": "check_weather",
    "builtinParams": {
      "city": "$param1",
      "period": "current"
    }
  }
}
```

`city` 为空时使用设置中的固定城市；固定城市也为空时使用 IP 定位。`本地`、`当地`、`这里`显式使用 IP 定位。

`period` 支持 `current`、`today`、`tomorrow`、`day_after`，以及“现在/当前/今天/明天/后天”。空字符串默认当前；可选 `defaultPeriod` 在捕获的 `period` 为空时生效，天气预报规则用它默认今天。其他字段会被拒绝，方便发现配置拼写错误。

内置 JSON 已增加四条天气规则，覆盖城市在前、日期在前、天气预报两种表达。天气规则仅容忍语法位置上的“天气天气”，不会全局删除人名或片名里的重复字。“搜索天气之子”和“我想看刘德华的电影电影”继续走影视搜索。

配置版本为 4。若电视存在 `/sdcard/levoice/commands.json` 或应用私有 `files/commands.json`，仍会优先读取它；安装新版 APK 不会自动覆盖外部规则，需要同步实际使用的指令文件。

## 网络行为

- IP 定位使用 `https://ipwho.is/`，不指定 IP，让服务按请求的公网出口判断；只请求 success/latitude/longitude 字段。定位失败会提示直接说城市，不会伪造默认城市。
- 城市名称或 IP 坐标通过 `/geo/v2/city/lookup` 转为城市、坐标和时区。
- 当前天气使用 `/weather/v1/current/{latitude}/{longitude}`。
- 每日预报使用 `/weather/v1/daily/{latitude}/{longitude}?days=3`。
- 请求 `localTime=true`，按查询城市的时区和返回的日期选择今天/明天/后天，不依赖数组顺序；没有目标日期就报错，不拿今天代替明天。
- 和风天气凭据只放在 `X-QW-Api-Key` 请求头，IP 服务不会收到它。所有请求禁止自动重定向，避免密钥被转发到其他域名。
- 单次连接超时 8 秒、单次读取超时 12 秒，解压后的响应最大 1 MiB；不自动重试失败请求。一个查询可能先后进行 IP、城市和天气三个请求，这些超时不是整个查询的总时限。
- 天气缓存 5 分钟，城市缓存 24 小时，IP 定位缓存 30 分钟；仅内存缓存，界面标注查询时间和缓存状态。切换网络后，IP 缓存最多保留 30 分钟；指定城市可立即覆盖。
- 天气结果显示和风天气来源链接及接口返回的归因信息。查询时间是应用取得结果的时间，不冒充气象观测时间。
- API 认证失败、权限/额度不足、限流、网络失败、数据缺失分别有提示。现有 API 权限或余额不足需在控制台处理，代码不会自动开通付费套餐。

## 本次实际验证

- 77 项自动测试通过，四种 ABI 的 debug APK 均构建成功。
- 使用新凭据执行生产 Kotlin 代码，电脑端成功查询北京当前天气和明日预报；默认 IP 查询也成功。电脑的代理出口被定位到日本，结果明确标注 IP 定位。
- 在这台 Android 6 电视的应用 UID 下执行相同天气客户端，定位到北京东城，并成功取得当前天气和明日预报。最终 APK 已覆盖安装、重启，并用安装包中的默认客户端再次验证成功。
- 电视首次请求暴露了系统缺少 ISRG Root X1 的问题。已从 Let's Encrypt 官方下载并核对根证书，仅为和风天气连接增加该根证书；默认系统信任链继续保留，域名、签名和有效期校验均未关闭。
- 主界面在电视上正常显示，日志确认加载内置 v4 配置，共 39 条指令。未使用真实麦克风完成口述查询；该步骤仍需遥控器实测。
