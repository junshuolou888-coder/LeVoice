# 新电视厂商语音适配版

适用对象：2026-09-23 实测的 Hi3751V560 / Android 12（API 31）/ armeabi-v7a 电视。该固件固定调用 `com.stv.voice/com.stv.voice.WindowService`；此构建提供相同入口，将按键交给本地识别界面。普通版仍为 `com.localvoicetv`。

## 构建与平台签名

```sh
# 普通版，默认不需要厂商签名
./gradlew assembleDebug -PtvIntegration=standard -PspeechModel=2023 -PspeechRuntime=modern

# 厂商适配版，生成未签名 release APK，交给厂商平台签名
./gradlew assembleRelease -PtvIntegration=stv -PstvTargetSdk=29 -PspeechModel=2023 -PspeechRuntime=modern
```

当前平台输入包：`app/build/outputs/vendor-signing/LeVoice-STV-2023-armv7-target29-for-platform.apk`。
该包由 `LeVoice-STV-2023-armv7-target29-unsigned.apk` 预签生成，仍须平台最终签名。
原始构建输出：`app/build/outputs/apk/release/app-armeabi-v7a-release-unsigned.apk`。

| 项目 | 值 |
| --- | --- |
| applicationId | `com.stv.voice` |
| 代码 namespace / 启动 Activity | `com.localvoicetv` / `com.localvoicetv.MainActivity` |
| sharedUserId | `android.uid.system`，与现有原厂包保持一致 |
| versionCode | `33022821`，高于原包 `33022820`；后续用 `-PstvVersionCode=...` 递增 |
| minSdk / targetSdk | 24 / 29；运行设备仍为 Android 12，兼容平台仅输出 V1 的签名方式 |
| 模型 / 运行库 | 2023 INT8 / Sherpa 1.13.8，单一模型，不额外安装模型 APK |
| 签名 | 构建不签名，不使用 debug 密钥，也不在工程内保存厂商私钥 |

平台必须使用这台电视对应的系统签名，签后保持 native `.so` 不压缩并正确对齐。

最初 targetSdk=31 的版本要求 V2 或更高签名。平台两次都只输出 V1，因此当前厂商版默认 targetSdk=29，让 Android 12 使用受支持的旧应用签名兼容规则；厂商证书匹配和 APK 完整性检查仍必须通过。普通版 targetSdk=36 不变。若平台后续支持 V2+，可用 `-PstvTargetSdk=31` 恢复原目标级别。targetSdk 调整会选择较旧的权限、存储和后台执行兼容行为，不改变电视系统版本。

## 早期按键协议与生命周期（33022821/33022822）

- 组件：`com.stv.voice.WindowService`，不向普通应用导出，与原厂一样供系统调用。
- 按下：`com.letv.openmic.with.hardware`，立即进入前台服务，再打开或复用识别 Activity，并开始当前按键对应的录音。
- 松开：`com.letv.closemic.with.hardware`，停止录音、结束前台服务。孤立的松开不会打开界面。
- 重复按下只处理一次。松开早于界面创建时取消待处理按下；模型加载期间的按下提示等待，不在加载完成后自动补录。
- 冷启动模型约需 40 秒；首次打开请等准备就绪后再按语音键。该版本不增加第二份模型，也不常驻第二个识别器。
- 松开丢失时 30 秒后强制停止；离开识别界面或服务销毁也停止本次按键录音。进程重启不自动恢复录音。
- 厂商版移除无障碍按键服务，使用系统组件入口。普通版保留既有配置。

这不是原厂所有接口的完整替代实现，仅适配已核实的硬件按键协议。蓝牙遥控器音频仍走电视已有的 `ble_audio` 驱动；之前收到全零 PCM，因此必须以签名后实测为准，不能把包名覆盖或界面聆听状态当作音频接通。
