# LeVoice 语音指令引擎

语音识别结果先交给 `CommandRegistry` 匹配，再由 `CommandExecutor` 执行命中的 `action`。匹配句式、优先级、排除词和已有类型的跳转参数都在 JSON 中配置。

本文对应 `default_commands.json` 的第 3 版配置。匹配器使用确定性的规则评分，不调用大模型；分数用于排序，不代表识别正确率。

## 重复词如何处理

“我想看刘德华的电影电影”需要提取演员“刘德华”。旧演员规则只接受一个句尾类别词，因此会漏匹配，随后通用搜索把“刘德华的电影电影”作为查询内容。

不能在整句话中无条件删除重复片段。例如 `(.{2,})\1+` 会把“哈哈哈哈”改成“哈哈”，也会改变重复的人名或片名。当前标准化只统一小写并去除空白和 `，。！？、,.!?`，保留重复内容。

容错放在演员规则的尾部：

```json
{
  "id": "search_actor_movies",
  "displayName": "搜索演员影片",
  "regex": "^(?:我想看|我想搜|我想找|搜索|搜一下|找一下)(.+?)的(电影|影片|电视剧|综艺|视频|戏|剧)(?:\\2)*$",
  "action": {
    "type": "activity",
    "intentAction": "com.letv.leso.desktop.receiver",
    "intentExtras": {
      "type": 1,
      "resource": 1,
      "value": "{\"keyword\":\"$param1\",\"fulltext\":\"$param1\",\"isActorSearch\":true}"
    }
  }
}
```

第一个捕获组 `(.+?)` 是 `$param1`，保存演员文本；第二组保存类别词，例如“电影”。JSON 中的 `\\2` 解析为正则的 `\2`，表示重复第二组刚刚匹配的同一个词。`*` 允许额外重复零次或多次。

| 输入 | 命中 | `$param1` |
| --- | --- | --- |
| 我想看刘德华的电影 | 演员搜索 | 刘德华 |
| 我想看刘德华的电影电影 | 演员搜索 | 刘德华 |
| 我想看刘德华的电视剧电视剧 | 演员搜索 | 刘德华 |
| 我想看哈哈哈哈的电影电影 | 演员搜索 | 哈哈哈哈 |
| 搜索电影电影 | 通用搜索 | 电影电影 |
| 搜索电影人生 | 通用搜索 | 电影人生 |
| 搜索天天向上 | 通用搜索 | 天天向上 |

这条规则只容忍类别词连续重复。“电影电视剧”这种混合尾部、人名识别错误、句中任意口吃，都不会被自动改写。它根据句式提取演员位置的文本，不验证该文本是否是真实演员姓名。以后增加类别词或句式，修改相应 JSON 正则即可。

通用搜索保留触发词后的完整文本，并配置 `priority: -1`。例如“搜索电影人生”保留“电影人生”，不会自动把开头的“电影”当成分类词删掉。因此，“搜索电影战狼”也会搜索“电影战狼”；需要支持分类检索时，应另写含明确分隔方式的规则。

## 候选匹配与冲突处理

加载配置时，匹配器编译正则，并标准化关键词、后缀和排除词。每次识别不再重新编译所有正则。`reload()` 先准备完整的新配置，再替换当前配置。

匹配时先排除包含 `excludeKeywords` 的指令，然后检查每条指令的所有匹配方式，保留该指令得分最高的候选，最后对候选排序。

```text
得分 = 基础分 + 覆盖度加分 + priority × 10
覆盖度加分 = floor(实际匹配文字长度 / 标准化输入长度 × 100)
```

| 匹配方式 | 基础分 | 覆盖度加分 |
| --- | ---: | --- |
| `EXACT`：输入与某个关键词相等 | 1000 | 不加 |
| `REGEX_FULL`：正则匹配整个输入 | 800 | 不加 |
| `REGEX_PARTIAL`：正则只匹配输入的一部分 | 600 | 加 |
| `CONTAINS`：输入包含关键词 | 400 | 加 |
| `SUFFIX`：输入以指定后缀结尾 | 400 | 加 |

旧版后缀固定得到 600 分，导致“设置”抢走“网络设置”。现在后缀和包含匹配共用基础分，匹配文字越长，覆盖度越高。同一条指令即使同时有关键词和后缀，也会比较两种结果。

排序依次比较：得分降序、匹配文字长度降序、匹配方式顺序 `EXACT → REGEX_FULL → REGEX_PARTIAL → CONTAINS → SUFFIX`，最后按唯一 `id` 的字典序排列。等长、等分时，明确关键词优先于后缀兜底，例如“蓝牙”优先于“设置”。

`priority` 默认是 0，仍按 `priority × 10` 加分。它允许跨匹配类型调整；数值过大也能压过精确匹配，应先收窄规则，再用小幅优先级解决已确认的冲突。

| 输入 | 候选及得分 | 选择结果 |
| --- | --- | --- |
| 我想看刘德华的电影电影 | 演员正则 800；通用搜索 790；电影关键词 418 | 演员搜索 |
| 请打开网络设置 | 网络设置关键词 457；设置后缀 428 | 网络设置 |
| 打开蓝牙设置 | 蓝牙关键词 433；设置后缀 433 | 蓝牙设置，关键词优先 |
| 打开刘德华的明星详情 | 明星详情正则 810；普通详情正则 800 | 明星详情 |

完全同分、同长度、同方式的不同规则仍可能有语义冲突。按 `id` 选择只是让结果不再依赖 JSON 数组顺序，并不代表匹配器理解了用户意图。此时 Logcat 会打印 `Ambiguous rules`，应调整 `priority`、正则或排除词。

`rankCandidates(text)` 返回排序后的候选列表，每项含 `entry`、`variables`、`score`、`matchType` 和 `matchedText`。`match(text)` 返回第一项，同时在 `CommandRegistry` 日志中显示前三个候选，便于定位谁抢走了指令。

```json
{
  "id": "open_desktop_movie",
  "displayName": "电影",
  "keywords": ["电影", "电影桌面", "打开电影桌面"],
  "excludeKeywords": ["搜索", "我想看"],
  "priority": 0,
  "action": {
    "type": "activity",
    "intentAction": "com.stv.launcher.action.start",
    "intentExtras": {
      "type": "1",
      "value": "{\"pluginid\":\"com.stv.template.movie\"}"
    }
  }
}
```

空关键词、空后缀和空排除词会被忽略。只匹配空字符串的正则不会触发动作。非法正则会记录指令 ID 并禁用该条正则，该指令的有效关键词及其他指令仍可使用。空白或重复 ID、缺少必要字段的 action 会让整份配置校验失败，加载器继续尝试下一个配置来源。

## 通用跳转

`CommandExecutor` 根据 `action.type` 分发。新增已支持类型的跳转只需填写 JSON；新增内置业务能力仍需 Kotlin 实现，天气查询已注册为 `check_weather`，通过 `builtinParams` 传入城市与日期，详见 [联网天气](联网天气.md)。

| `type` | 执行方式 | 主要字段 |
| --- | --- | --- |
| `activity`、兼容别名 `intent` | `startActivity()` | Intent 参数 |
| `broadcast` | `sendBroadcast()` | Intent 参数 |
| `service` | `startService()`，或按配置启动前台服务 | Intent 参数、`serviceMode` |
| `uri` | 默认 `ACTION_VIEW` 后 `startActivity()` | `uri` 和共用 Intent 参数 |
| `builtin` | 调用已有内置动作 | `builtinAction` |

`activity`、`uri`、`broadcast`、`service` 现在共用一个 Intent 构造器，支持以下参数：

| 字段 | 作用 |
| --- | --- |
| `intentAction` | Intent action；Activity/URI 有地址但未声明 action 时默认 `ACTION_VIEW` |
| `intentData` | Data URI；`type=uri` 使用 `uri` 字段，不能同时提供不同的 `intentData` |
| `intentType` | MIME 类型；与 Data 同时存在时使用 `setDataAndType()` |
| `intentPackage` | 将目标限制在指定应用中；仍需提供 action、地址或组件来确定目标页面 |
| `intentClass` | 显式指定组件，必须同时有包名；支持 `.PlayerActivity` 这样的相对类名 |
| `intentCategories` | Category 字符串数组 |
| `intentFlags` | 受支持的名称，或十进制/十六进制数值字符串组成的数组 |
| `intentExtras` | 基础类型参数，或带 `type`、`value` 的类型声明 |

支持的 flag 名称：`FLAG_ACTIVITY_NEW_TASK`、`FLAG_ACTIVITY_CLEAR_TOP`、`FLAG_ACTIVITY_SINGLE_TOP`、`FLAG_ACTIVITY_CLEAR_TASK`、`FLAG_ACTIVITY_NO_HISTORY`、`FLAG_ACTIVITY_NO_ANIMATION`、`FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS`、`FLAG_ACTIVITY_REORDER_TO_FRONT`、`FLAG_INCLUDE_STOPPED_PACKAGES`、`FLAG_RECEIVER_FOREGROUND`，以及 `FLAG_GRANT_READ_URI_PERMISSION`、`FLAG_GRANT_WRITE_URI_PERMISSION`、`FLAG_GRANT_PERSISTABLE_URI_PERMISSION`、`FLAG_GRANT_PREFIX_URI_PERMISSION`。

数值写法例如 `"intentFlags": ["0x04000000", "536870912"]`，值必须在 32 位范围内。未知名称或溢出值会报错，不再静默忽略。Activity/URI 会自动附加 `FLAG_ACTIVITY_NEW_TASK`；广播和服务不会自动附加。包名限制、Data 与 MIME 的行为对应 [Android Intent API](https://developer.android.com/reference/android/content/Intent)。

正则的捕获组对应 `$param1`、`$param2` 等变量。Intent 的 action、data、MIME 类型、组件、category、flags 和字符串 extra 值支持变量替换，URI 字符串也支持。变量按完整名称单次替换：`$param1` 不会破坏 `$param10`，参数值中出现 `$param2` 也不会再次展开。缺少变量时，在发起跳转前报错。

`${param1}` 和 `${param1:raw}` 表示原样替换；`${param1:uri}` 表示把该参数作为 URI 的一个片段进行编码。例如：

```json
{
  "type": "uri",
  "uri": "example://search?q=${param1:uri}&page=1",
  "intentPackage": "com.example.player",
  "intentExtras": {"source": "voice"}
}
```

参数“刘德华 &page=99”会完整留在 `q` 的值中，固定的 `page=1` 不会被改写。旧的 `$param1` 写法仍原样替换；如果变量本身代表完整 URI，应使用原样替换。这里的 URI 指普通 scheme/deep link，不解析浏览器专用的 `intent://...#Intent;...;end` 序列化语法。

不要给依赖捕获参数的命令添加不提供参数的占位关键词。

### Extra 参数类型与嵌套 JSON

原有的字符串、Int、Long、Boolean、Float、Double 参数保留原类型。需要将捕获文本转为数值、指定数组，或生成嵌套 JSON 时，使用显式类型：

```json
{
  "type": "activity",
  "intentAction": "com.example.SEARCH",
  "intentExtras": {
    "page": {"type": "int", "value": "$param1"},
    "names": {"type": "stringArray", "value": ["$param2", "其他"]},
    "value": {
      "type": "json",
      "value": {"keyword": "$param2", "isActorSearch": true}
    }
  }
}
```

| 声明的 `type` | 传给 Intent 的类型 |
| --- | --- |
| `string` | String；数字、布尔值也可显式转为字符串 |
| `int`、`long`、`float`、`double`、`boolean` | 对应的基础类型 |
| `stringArray`、`intArray`、`longArray`、`booleanArray` | 对应数组，`value` 必须是 JSON 数组 |
| `json` | 序列化后的 JSON 字符串，`value` 必须是对象或数组 |

`json` 类型先递归替换对象和数组里的字符串值，再由 JSON 序列化器处理引号、换行和反斜杠。数值、布尔值和 JSON null 保留原状。旧的 `"value": "{\"keyword\":\"$param1\"}"` 写法仍可用，也会先解析结构再注入参数。旧字符串如果能解析为对象或数组，输出时会重新序列化；若必须保留文本格式，使用显式 `type=string`。

不支持的类型、顶层 null extra、非法数字或布尔值会报错，并指出出错的 extra 名称。整数转换不会截断小数，浮点参数不接受 NaN 或 Infinity。布尔参数只接受 `true` 和 `false`。

打开网页的 URI 示例：

```json
{
  "id": "open_help",
  "displayName": "打开帮助页面",
  "keywords": ["打开帮助页面"],
  "action": {"type": "uri", "uri": "https://example.com/help"}
}
```

URI 跳转现在也支持 package、extras、categories、MIME 类型和 flags。也可继续使用 `activity` 加 `intentAction: "android.intent.action.VIEW"` 和 `intentData`：

```json
{
  "id": "play_video",
  "displayName": "播放测试视频",
  "keywords": ["播放测试视频"],
  "action": {
    "type": "activity",
    "intentAction": "android.intent.action.VIEW",
    "intentData": "https://example.com/video.mp4",
    "intentType": "video/*"
  }
}
```

广播和服务沿用同一个 Intent 构造器：

```json
{
  "type": "broadcast",
  "intentAction": "com.example.REFRESH",
  "intentExtras": {"source": "voice", "refresh": true}
}
```

```json
{
  "type": "service",
  "serviceMode": "normal",
  "intentPackage": "com.example.app",
  "intentClass": "com.example.app.RefreshService"
}
```

`service` 必须显式填写包名和类名。`serviceMode` 默认是 `normal`；设为 `foreground` 时，Android 8.0 及以上调用 `startForegroundService()`，旧系统调用 `startService()`。前台服务的通知和前台状态应由目标服务自己建立。该选项不能绕过系统的后台启动限制。启动接口返回 null 时会提示未找到服务，不再报告执行成功。对应行为见 [Android Context API](https://developer.android.com/reference/android/content/Context#startService(android.content.Intent))。

内置动作支持 `volume_up`、`volume_down`、`toggle_mute` 和 `go_home`。缺少目标页面或组件、被目标应用拒绝调用时，会保留原始异常原因并给出提示。广播发送成功只表示系统接受了发送请求，不代表接收方已经完成业务处理。

## 配置加载与验证

完整配置最外层包含 `version`、`hotwordsScore` 和 `commands`。单条指令包含唯一 `id`、`displayName`、至少一种有效匹配规则以及 `action`；`hotwords` 是语音识别热词，与匹配分数无关。

加载器依次读取第一份能够成功解析并通过 ID、action 必填字段校验的配置：

1. `/sdcard/levoice/commands.json`
2. 应用私有目录中的 `commands.json`
3. APK 内的 `assets/default_commands.json`
4. 前三项都失败时，使用代码中的系统设置兜底指令。

这个顺序不比较 `version` 大小。电视上若已有外部 JSON，安装新 APK 后仍会优先使用外部文件；需要把新规则同步到实际生效的配置，并重启应用。当前界面在启动时加载配置，没有自动监视文件修改。

回归测试直接读取 APK 使用的同一份默认 JSON，覆盖演员类别词重复、保留片名、具体设置优先、全部声明关键词以及多种指令排列顺序。还检查正则失效、空规则、排除词、优先级、配置重新加载和候选分数。

```sh
./gradlew testDebugUnitTest assembleDebug
```

本项目已有的本地构建工具也可使用：

```sh
JAVA_HOME="$PWD/.tools/jdk/Contents/Home" \
GRADLE_USER_HOME="$PWD/.gradle-local" \
.tools/gradle-8.11.1/bin/gradle testDebugUnitTest assembleDebug
```

本地单元测试验证文本匹配和 JSON 解析；Robolectric 测试检查 Android 6 和 Android 9 环境中的 Intent 字段、参数类型及分发接口选择。APK 构建验证编译、打包。测试中的目标 Context 记录分发请求，不安装或启动电视上的第三方应用；麦克风识别输出、外部应用实际处理和电视端生效配置仍需真机验证。

源码入口：`CommandConfig.kt` 定义模型，`CommandConfigLoader.kt` 加载配置，`CommandRegistry.kt` 排序候选，`CommandParameters.kt` 处理变量和参数类型，`CommandExecutor.kt` 构造 Intent 并执行动作，`default_commands.json` 存放默认规则。

## 联网内置动作

`action.builtinParams` 是可选字符串映射，使用通用变量替换。`check_weather` 支持 `city`、`period` 和 `defaultPeriod`。执行器返回 `PENDING` 时表示已开始异步请求，界面等待结果后再显示完成状态；离开页面或发起新命令会取消旧查询。详见 [联网天气](联网天气.md)。
