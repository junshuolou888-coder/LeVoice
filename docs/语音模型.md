# 本地流式语音模型

语音识别先把录音转换为文字，随后 JSON 指令引擎才匹配和执行。转写“青岛市天气”得到“青岛是天气天气”时，传入天气查询的地名会是“青岛是”；扩大 JSON 规则不能证明模型识别率提高了。

## 工程模型与打包切换

当前默认打包 2023 INT8。两套完整模型放在工程根目录的 `models/zipformer-zh-2023/` 和 `models/zipformer-zh-2025/`，不再依赖隐藏的 `.tools` 目录。

| 打包选项 | 模型 | 必要模型文件大小 |
| --- | --- | --- |
| `2023`（默认） | multi-zh-hans 2023-12-12，encoder/joiner INT8、decoder FP32 | 约 72.8 MiB |
| `2025` | 中文 2025-06-30，encoder/joiner INT8、decoder FP32 | 约 159.6 MiB |
| `baseline` | 最初的 14M 轻量模型 | 原 assets 文件 |

修改 `gradle.properties` 中的 `speechModel`，或者单次指定：

```sh
./gradlew assembleDebug -PspeechModel=2023
./gradlew assembleDebug -PspeechModel=2025
./gradlew assembleDebug -PspeechModel=baseline
```

只把选中的模型放进 APK，未选中的模型和 14M 回退文件不会同时打包。缺失或损坏的文件在 Gradle SHA-256 校验时直接报错。切换无需 `clean`，安装包输出路径不变，因此需要同时保留多个 APK 时应先重命名保存。

应用只加载打包选定的模型；早期试用留在电视应用目录的模型和 `enabled` 标记不再参与选择。新 APK 可以独立安装到其他电视，卸载重装也不需要再复制模型。回退通过打包并安装另一版 APK 完成。

录音仍在电视本地处理，不上传录音。运行库由 `speechRuntime` 选择：默认 `modern` 使用 1.13.8（最低 API 24），`android6` 使用 1.12.39（最低 API 23）；采样率 16 kHz；2023/2025 使用官方示例的 greedy 解码，不添加命令热词，14M 保留原来的 beam search 配置。界面和日志显示当前模型年份。

固定来源、文件名及校验清单见 [models/README.md](../models/README.md)。

## 真机对照测试

构建应用与设备测试 APK 并安装，参考 WAV 固定读取电视应用目录下的 `speech-models/zipformer-zh-2025/test_wavs`（沿用前次相同音频）。当前打包模型直接从 assets 测试；2025 也可校验后读取此前独立安装的文件。baseline 需要先安装 baseline APK。

```sh
adb -s 电视IP:5555 shell am instrument -w -r -e speechBenchmark 2023 com.localvoicetv.test/com.localvoicetv.CommandEngineDeviceChecks
adb -s 电视IP:5555 shell am instrument -w -r -e speechBenchmark 2025 com.localvoicetv.test/com.localvoicetv.CommandEngineDeviceChecks
```

测试使用相同 WAV，按 100 毫秒分块输入，不调用麦克风，不执行识别后的指令。输出加载时间、音频时长、解码耗时、识别文字和进程 PSS。RTF 是解码耗时除以录音时长，低于 1 才有平均实时处理的余量；它不包括真实说话时等待音频、断句等待和模型启动时间。

三个官方示例只能检查模型运行与速度，不能代表用户在电视旁说话的准确率。验收口令至少包括“切换到儿童桌面”“青岛市天气”“看一下今天的天气”和人名搜索，并直接核对 `VoiceRecognition` 的最终原文。

## 2026-09-22 初次试运行结果（旧部署方式）

这台 Android 6、4 核电视上使用相同的 3 个官方 WAV 测试，未使用用户麦克风录音：

| 模型 | 加载耗时 | 三段音频的 RTF | 结束时进程 PSS |
| --- | --- | --- | --- |
| 内置 14M，beam search（未注入热词） | 1.47 秒 | 0.27 / 0.32 / 0.28 | 约 65 MiB |
| 2025 中文 INT8，greedy search | 13.24 秒 | 0.81 / 0.76 / 0.76 | 约 229 MiB |

两种解码方式与各自配置一并比较，不是只替换权重的受控准确率评测。增强模型在第二段样例中输出“全球金融动荡”，轻量模型输出“全球金融动量”。日常口令是否改善仍需用户试说。

增强模型分块计算的最大单次耗时在这次测试中为 349 毫秒，因此录音缓冲容量增加到至少 2 秒，避免原来较小的缓冲在分块计算时溢出；每次读取仍为 100 毫秒，不人为等待填满缓冲。真正的语音响应还包括端点等待与调度，不能直接把这些离线样例的 RTF 当作最终交互延迟。

增强模型启用后的应用启动日志确认 `Model ready: 中文增强模型 · Zipformer INT8`，含文件校验的启动耗时约 14.4 秒。

## 2023 APK 内置模型试运行

2023 模型从 APK assets 加载，沿用前次 3 个官方 WAV、2 线程、greedy 解码：

| 模型 | 模型加载 | 三段音频 RTF | 测试结束进程 PSS |
| --- | --- | --- | --- |
| 2025（之前独立文件加载） | 13.24 秒 | 0.806 / 0.758 / 0.759 | 229.4 MiB |
| 2023（本次 APK assets 加载） | 18.03 秒 | 0.490 / 0.418 / 0.423 | 134.3 MiB |

PSS 少约 95 MiB（约 41%）。加载方式和设备状态不同，启动耗时不能作为模型本身的严格对照；本次模型虽小，首次加载并没有更快。RTF 是解码计算耗时比，不含说话等待和端点等待。

准确率存在取舍：2023 在第 2、3 段将“金融动荡”输出为“金融动衡”，2025 对应片段正确。三段参考音频不能代表日常遥控器口令；需要实际试说“切换到儿童桌面”“青岛市天气”“看一下今天的天气”“我想看刘德华的电影”。

两种打包选项均构建成功，检查 APK assets 确认每包只含所选模型及命令 JSON，模型逐文件 SHA-256 与清单一致。2023 构建通过 80 项 JVM 测试；真机参考音频测试通过。arm64 调试 APK：2023 约 124.8 MiB，2025 约 211.6 MiB。

正常主界面启动日志确认加载 `Zipformer 2023 INT8`，耗时 17.67 秒；准备就绪后的应用 PSS 为 136852 KiB（约 133.6 MiB），上次 2025 主界面快照约 226.3 MiB，少约 92.7 MiB（41%）。这是快照对比，不是连续识别峰值。8 项 Android 真机指令回归检查全部通过；测试 APK 已卸载。

## 2026-09-23 新电视安装测试

设备：AndroidTV / Hi3751V560，Android 12（API 31），系统 ABI 为 armeabi-v7a，4 核 Cortex-A55，系统可见内存约 1.93 GiB。安装 32 位 ARM APK，仍使用 2023 INT8 模型。

旧 `sherpa-onnx-1.12.39-android6.aar` 的 32 位 ONNX Runtime 1.24.3 在模型加载阶段触发 `SIGBUS/BUS_ADRALN`。真机崩溃位置 `libonnxruntime.so+0x8a3616` 是未对齐地址上的 LDRD。上游也有 [同位置的 32 位崩溃报告](https://github.com/k2-fsa/sherpa-onnx/issues/3508)，但本项目修复结论以本机复测为准。

切换工程已有的 `sherpa-onnx-1.13.8.aar`（内含 ONNX Runtime 1.28.2）后，模型加载及三段参考音频测试均通过，不再出现该崩溃。增加独立的运行库选择：

```sh
# 新电视，Android 7 及以上；当前 gradle.properties 默认值
./gradlew assembleDebug -PspeechModel=2023 -PspeechRuntime=modern

# 原 Android 6 电视
./gradlew assembleDebug -PspeechModel=2023 -PspeechRuntime=android6
```

APK 只包含所选模型和所选运行库。`modern` 明确将 minSdk 设为 24，避免安装到 Android 6 后才出现原生符号加载失败；`android6` 仍为 23。

测试结果：

- 参考 WAV 加载模型 39.30 秒；RTF 分别为 1.049、1.070、1.081，略低于实时处理速度，长句可能有积压延迟。
- 测试结束 PSS 为 149772 KiB（146.3 MiB）；正常主界面加载 39.37 秒，PSS 快照 155252 KiB（151.6 MiB）。
- 80 项 JVM 测试通过；9 项 Android 真机检查通过，包括重复电影后缀、参数注入和实际 IP 定位天气请求。
- 天气凭据仅写入应用私有目录，未打包；不指定城市可获取 IP 定位天气。
- 实际点击“开始说话”后，系统报告 `MIC`、16 kHz、单声道 PCM16、`silenced:false`，界面进入聆听状态；本轮没有有效麦克风转写，不能据此认定遥控器语音准确率或实际声音采集已验收。测试后已停止录音。
- 临时测试 APK 已卸载；主应用保留。可安装包另存 `app/build/outputs/model-trials/LeVoice-2023-modern-armeabi-v7a.apk`。

### 新电视系统语音冲突处理

2026-09-23，日志确认遥控器 `KEYCODE_VOICE_ASSIST` 会启动极光语音 `com.stv.voice/.WindowService` 并抢占音频焦点。按用户要求，仅对用户 0 停用 `com.stv.voice` 并停止其进程，未卸载系统文件。原始状态为 `enabled=0`。

```sh
adb -s 192.168.1.100:5555 shell pm disable-user --user 0 com.stv.voice
adb -s 192.168.1.100:5555 shell am force-stop --user 0 com.stv.voice

# 恢复原始默认启用状态
adb -s 192.168.1.100:5555 shell pm default-state --user 0 com.stv.voice
```

复测模拟语音键（231）后，原语音进程没有重新启动，前台保持本地语音助手。系统仍尝试调用禁用的服务并记录 `not found`；停用不等于将系统语音键自动映射给本应用，当前使用应用“开始说话”按钮。


### 新电视语音键与音频接管排查（尚未验收）

- 固件 `PhoneWindowManager` 明确启动 `com.stv.voice/com.stv.voice.WindowService`，按下与松开分别发送 `com.letv.openmic.with.hardware` 和 `com.letv.closemic.with.hardware`。停用原厂包后仍尝试同一组件，不会自动改为第三方应用。
- 初版无障碍按键接管服务已绑定，但实按与内核模拟语音键均未出现应用按键回调。补充事件订阅的构建已安装；安装后设备未启用该服务，不能把此构建记为接管成功。
- 应用录音时 `MIC`、16 kHz、单声道 PCM16、未被系统静音，但观测到的采样 RMS/peak 均为 0；`audio_ble_default` 报 HID 读取超时。该问题发生在模型输入之前，模型文件测试通过不代表遥控器音频采集通过。
- 音频策略将输入路由到 `ble_audio`，由厂商 `audio.stub.default.so` 读取蓝牙 HID 数据并解码；尚未取得有效遥控器 PCM。
- 原厂 APK 声明 `android.uid.system`，证书 DN 含 `cultraview@cultraview.com`，SHA-256 为 `cc079d3a727b1b53a7f3376eed1720988d63873517c4303578031ec54b8013c7`。同包名覆盖需要匹配的签名能力并保持共享 UID 兼容，不能仅改 applicationId 后用 debug 签名安装。
- 若厂商可提供匹配签名，适配构建还必须提供完整的 `com.stv.voice.WindowService` 组件和上述按下/松开协议，满足前台服务要求；签名和按键接通后仍需单独验证蓝牙音频采集。
- 排查结束时已停止应用录音；原厂语音保持停用。无障碍服务设置当前仅保留原有 HiRMService，临时 APK 下载服务已关闭。
